# W25Q64
## W25Q64 使用方法

### 1. 硬件连接

SPI1 使用软件片选，连接如下：

| STM32F103 | W25Q64 |
|---|---|
| PA4 | `/CS` |
| PA5 | `CLK` |
| PA6 | `DO/SO`（MISO） |
| PA7 | `DI/SI`（MOSI） |
| 3.3 V | `VCC` |
| GND | `GND` |

MCU 与 Flash 共地。 `/CS` 加上拉，让 MCU 复位或启动时 Flash 保持未选中。PA4 已配置为软件控制片选，SPI 使用软件 NSS。

### 2. SPI 与 DMA 配置

W25Q64 支持 SPI Mode 0 或 Mode 3；当前工程使用 Mode 0、MSB 优先、8 位数据。预分频为 `/4` 且 APB2 时钟为 64 MHz，SPI 时钟约为 16 MHz。

SPIF 当前使用 DMA，TX/RX DMA 都配置为内存地址递增的 **Normal（普通）模式**，并启用相关 DMA 中断。

### 3. 初始化与读写流程

1. 初始化 HAL、GPIO、DMA 和 SPI，并让 PA4 处于高电平。
2. Flash 上电后等待至少 **120 ms**，再发送指令。
3. 调用 `spif_init(&w25q64, &hspi1, GPIOA, GPIO_PIN_4)` 初始化驱动、识别芯片。
4. 用 `spif_read()` 读取、`spif_write()` 写入；写入前先用 `spif_erase_sector()` 擦除对应扇区。
5. 检查每个 SPIF 返回值，并将读回数据与原始数据比较。

预期 JEDEC ID 为 `EF 40 17`。注意：SPIF 内部采用其兼容的快速读取命令，并非必须与手册示例中的 `03h` 完全相同。

### 4. 擦除和编程注意事项

- Flash 擦除后内容为 `0xFF`；NOR Flash 编程只能将位从 `1` 改为 `0`。要再次写入已使用区域，通常必须先擦除所在扇区。
- Page Program 一页最多 **256 字节**，且不能跨页直接编程。SPIF 的 `spif_write()` 会拆分跨页写入，但不会自动擦除。
- `spif_erase_sector()` 的参数是**扇区编号**，不是字节地址。可通过 `SPIF_ADDRESS_TO_SECTOR(&w25q64, address)` 计算。
- 视频上传会擦除 W25Q64 的扇区 0 至 186；这些扇区原有内容会被破坏，扇区 187 及之后不会被播放器使用。

## 播放 ikun.txt

`ikun.txt` 是 C 数组文本 `GIFData[744][1024]`，每帧为 SSD1306 128×64 单色缓冲区。固件播放前先显示“我不要期中考”和“哎呦你干嘛~”两页标题（点阵数据来自 `intro.txt`），各停留 2 秒，然后以 24 帧/秒循环播放。帧数据保存在 W25Q64 地址 `0x1000` 起；地址 0 保存上传完成标记和 CRC。未完成或校验失败的上传不会标记为有效视频。

### USART1 接线

使用 **3.3 V TTL USB 转串口适配器**，串口参数为 **115200 baud、8 数据位、无校验、1 停止位**：

| STM32F103 | USB-TTL 适配器 |
|---|---|
| PA9 / USART1_TX | RX |
| PA10 / USART1_RX | TX |
| GND | GND |

TX/RX 交叉连接并共地。不要将 RS-232 电平或 5 V 逻辑电平接到 MCU；适配器的 5 V/3.3 V 电源输出不要接入板子供电。

### 上传和播放

1. 编译并烧录固件，连接 OLED、W25Q64 和 USB-TTL。
2. 在 PC 安装 `pyserial`：`python -m pip install pyserial`。
3. 上传文本帧并通过 CRC 校验：

   ```powershell
   python .\scripts\upload_ikun.py --port COM3
   ```

   将 `COM3` 换成设备管理器中的串口号；源文件默认是仓库根目录的 `ikun.txt`，也可用 `--file` 指定。
4. 上传完成后 OLED 自动开始循环播放。更新同规格视频时再次运行上传命令即可；如果串口握手超时，复位开发板后重试。
